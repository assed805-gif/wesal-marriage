وصال — حزمة مراجعة وتطوير (Stage 3)
===================================
تم فحص الأرشيف المُرسل وتصحيح اختلاف اسم المتغير السري ودعم مفاتيح Supabase الحديثة sb_secret_.
لم يتم الربط فعليًا بمشروعك، ولم تُجرَ تجربة تشغيل حقيقية على Netlify أو Supabase.

السبب الحالي لظهور أرقام الطلب مع عدم حفظها:
الرابط المنشور يعرض النسخة الاستعراضية السابقة (كما يظهر من لافتة الصفحة).
يجب نشر نسخة الخادم أولًا. تغيير متغير البيئة وحده لا ينشر وظائف Netlify.

المتغيرات المطلوبة داخل Netlify (قيمها لا تُرسل في ChatGPT):
SUPABASE_URL = عنوان مشروع Supabase
SUPABASE_SECRET_KEY = مفتاح sb_secret_... من Supabase (أو SUPABASE_SERVICE_ROLE_KEY للمفتاح القديم فقط)
PUBLIC_ORIGIN = https://wesal-marriage.netlify.app
ADMIN_EMAIL = بريد مخصص للإدارة
ADMIN_PASSWORD = كلمة مرور قوية فريدة (16 حرفًا على الأقل)
ADMIN_SESSION_SECRET = نص عشوائي قوي 32 حرفًا على الأقل

انشر الحزمة عبر مشروع GitHub متصل بمشروع Netlify الموجود أو عبر Netlify CLI من جهاز حاسوب:
  npm install -g netlify-cli
  netlify login
  cd Wesal_Stage3_Reviewed
  netlify link  (اختر الموقع الموجود wesal-marriage، لا تنشئ موقعًا آخر)
  netlify deploy  (للمعاينة أولاً)
  netlify deploy --prod (فقط بعد تدقيق الحماية)

لا تستخدم Netlify Drop لنشر Functions؛ ينبغي التحقق من عملية البناء والنشر ودعم الدوال.
يمكن اختبار ظهور الدوال بعد نشر المعاينة بزيارة /.netlify/functions/health في رابط المعاينة.

ملاحظات أمنية تمنع الإنتاج حاليًا:
- لا توجد حماية متينة من التسجيل الآلي وإغراق واجهة التسجيل ومحاولات دخول المدير (rate limiting/CAPTCHA).
- يجب مراجعة صلاحيات SQL الفعلية وسياسات RLS وخطة الاحتفاظ/الحذف وبيان الخصوصية.
- واجهة الإدارة مبدئية وغير معدة بعد لإطلاق تجاري.
- نموذج الموافقة والنصوص القانونية تحتاج مراجعة قبل جمع بيانات حساسة.
- لم تنفذ اختبارات طرف إلى طرف لحفظ الطلب أو متابعة الطلب.
- الدفع لا يزال خارج النطاق.

لا تُدخل بيانات أو مفاتيح حقيقية في المحادثة. لا تطلب رسومًا من العملاء قبل نجاح الاختبار الأمني.
